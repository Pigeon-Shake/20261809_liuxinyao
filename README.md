## 二、类设计

**4 个私有数据成员**（超过 ≥2 的要求）：

| 成员 | 含义 |
| --- | --- |
| `title_` | 影片名 |
| `price_` | 原价 |
| `seat_` | 座位号 |
| `discount_` | 折扣率（1.0 为不打折，越小越便宜） |

另有静态成员 `total_` 统计在售票数：构造时 `++total_`，析构时 `--total_`。

**成员函数**：`print()`（打印票据信息）、`finalPrice()`（实付价格 = 原价 × 折扣率）、`changeSeat()`（改签换座）。

**运算符重载**：

| 运算符 | 语义 |
| --- | --- |
| `operator+` | 两张票合并成"套票"：价格相加，折扣取更优惠（更小）的，座位沿用左操作数 |
| `operator<` | 按实付价格比较，方便排序 |
| `operator==` | 同影片且同座位视为同一张票 |
| `operator<<` | 流输出（左操作数是 `ostream`，写成友元函数） |

## 三、构建与运行

```bash
mkdir build && cd build
cmake ..
make
./ticket
```

也可以一步到位：

```bash
cmake -B build && cmake --build build && ./build/ticket
```

## 五、我的说明

- 姓名：刘心尧

- 实现思路：
  - 构造函数用**初始化列表** `: title_(title), price_(price), seat_(seat), discount_(discount)` 依次初始化 4 个成员，参数均带默认值，支持全缺省构造；析构函数负责 `--total_` 并打印退票信息，便于观察对象生命周期；
  - `finalPrice()`、`print()`、`operator<`、`operator==` 都声明为 `const` 成员函数，保证不修改操作数；`operator+` 返回**新对象**，不改变左右操作数；
  - `operator<<` 必须写成友元：左操作数是 `ostream`，不能是 Ticket 的成员函数，通过友元直接访问私有成员并返回 `ostream&` 以支持链式输出；
  - 静态成员 `total_` 在类外定义并初始化为 0，用来统计当前在售票数，构造/析构各修改一次。
- 遇到的问题与解决：
  - 套票的座位号取谁的开始拿不定主意，最后约定沿用左操作数（`a + b` 取 a 的座位），并在注释里说明；
  - 一开始把 `operator<<` 写成了成员函数，编译报参数个数不匹配，查资料后明白二元运算符左操作数是 `ostream` 时只能用友元（或全局函数）实现；
  - `build/` 目录一度出现在 `git status` 里，通过 `.gitignore` 忽略 `build/`、`*.exe` 等产物解决。
